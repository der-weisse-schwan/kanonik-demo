K03Schritt „Reservierung anfragen“ fehlt im BPMN
Der aus dem Fachkonzept abgeleitete Baustein ci-anfrage-annehmen hat im vorhandenen Modell camunda-cloud/src/main/resources/reserve-tickets.bpmn kein Gegenstück.
Folgelücken: K13
Spricht dagegen: „ci-anfrage-annehmen“ ist der erste Schritt des Hauptprozesses. Der Code startet den Prozess in CinemaController.reserveSeat (POST /reservation); was vor dem Prozessstart geschieht, kann dort umgesetzt sein – dann fehlt kein Schritt im BPMN, sondern das Fachkonzept wird im Code vor dem Prozess erfüllt (Modellierungsentscheidung). Vor dem Start ruft die Methode auf: UUID.randomUUID, zeebeClient.newCreateInstanceCommand, Map.of, request.getSeats, request.getName.
Zu prüfen: Prüfen, ob der Code diese Aktivitäten des Schritts erledigt: Reservierungsnummer vergeben; Eingang der Reservierungsanfrage bestätigen; Reservierungsanfrage ablehnen. Fehlt eine davon auch im Code, bleibt die Lücke fachlich bestehen (dann eher im Code als im BPMN zu schließen).
Code: reserve-tickets.bpmn ↗		fehltBPMNA-4.1-1, A-4.1-2, A-4.1-3bestätigt

K16Regelwert „höchstens einer Reservierung“ wird nicht geprüft
Laut R-3 gilt „höchstens einer Reservierung“; keine Bedingung im Code prüft diesen Grenzwert.
Wo im Code: Keine Code-Stelle nennt „Reservierung“ erkennbar – die Prüfung gehört in die Klasse, die „Reservierung“ verwaltet (bzw. ihre Regeln/Policies). 		fehltCodeR-3bestätigt
