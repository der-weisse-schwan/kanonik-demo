Knowledge graph and spec-driven development

Spec-driven development means: the specification comes first, and everything else – process model, code, tests – follows it. In practice this link is quickly lost. The specification is a document, the code keeps evolving, and nobody knows exactly which requirement is implemented where.

Kanonik restores the link through a knowledge graph:

  • From the specification it reads terms, roles, requirements, business rules and processes – each with the place in the document it comes from.
  • From process models and code come processes, services, classes, methods and messages.
  • In the knowledge graph both sides are linked. Experts review the proposals and decide; every decision stays traceable.

This covers the typical tasks of specification-driven development:

TaskWhat Kanonik delivers
Traceabilityfrom the requirement via rule and process to the class in the code
Gap analysiswhat the specification requires but process or code do not implement – with evidence
Living documentationthe comparison runs again for every new version of document or code
Ubiquitous languageterms in German and English, synonyms, broader and narrower terms as in domain-driven design
