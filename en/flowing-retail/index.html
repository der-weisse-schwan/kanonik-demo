How this example came about

Choice

A well-known reference example for event-driven microservices: flowing-retail by Bernd Rücker, Kafka variant with Java and Zeebe. Six services (checkout, order, payment, inventory, shipping, monitor) talk via a Kafka topic; order and payment run as BPMN processes. This makes it possible to compare specification, process models and distributed code at the same time.

Preparation

We wrote the order-handling specification ourselves for this demo: roles, terms, processes from order to shipment, rules, requirements, domain model and a message table. Fixed were the variant and commit of the code, the project's three BPMN files and a list of expected gaps as test oracle. The language-model extraction was reviewed and accepted; after that everything runs without a language model.

What Kanonik did

Kanonik translated the specification into a knowledge graph, derived BPMN and a domain model, and read the existing BPMN processes and the code of all services: Kafka messages, Zeebe workers, process starts, correlations. From the code it generated an OpenAPI and an AsyncAPI description – which service sends or receives which message over which topic, pointing to every place in the code. The comparison specification ↔ BPMN ↔ code yields the gap list, measured against the test oracle.
